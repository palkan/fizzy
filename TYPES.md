# Types

Ruby code in `app/` and `lib/` is typed with [RBS](https://github.com/ruby/rbs) inline annotations and checked with [Steep](https://github.com/soutaro/steep). `bin/steep check` must pass.

Use the types: read a method's signature to learn what it takes and returns, and annotate the code you write. The goal is type checking that catches mistakes, so prefer code that type-checks over silencing Steep.

For how this setup came about, and what didn't work, see `docs/rbs-setup.local.md`.

## Commands

- `bin/steep check` — type check everything (configured in `Steepfile`). Don't pass paths: Steep then skips the inline signatures of the other files and may report success without checking anything. Filter the full output instead.
- `bin/steep server start`, then `bin/steep query hover app/models/card.rb:57:10` to see the inferred type at a position, and `bin/steep query definition Card.closed` to find where a method or constant is declared. `bin/steep server stop` when done.
- `bin/rails rbs:generate` — regenerate all generated signatures. Run it after changing the schema, routes, associations, scopes, `delegate`s, mixins, or concerns' `ClassMethods`. The pieces: `rbs:collection` (gem signatures), `rbs:rails` (rbs_rails, for models and route helpers), and `rbs:inline` (what inline RBS can't express). Generate in OSS mode (without `tmp/saas.txt`), so SaaS-only code doesn't leak into the signatures.

## Where signatures live

- Inline, in the Ruby source — the default for app code.
- `sig/rbs_rails/` — generated by rbs_rails: columns, associations, enums, model-file scopes, route helpers. Don't edit.
- `sig/generated/inline.rbs` — generated by `bin/rails rbs:inline` (`lib/tasks/rbs/inline_gaps.rb`): implicit Zeitwerk namespaces, multi-module mixins, concerns' `ClassMethods`, methods Rails macros define (`delegate`, `alias_method`, `store_accessor`, `attribute`, `class_attribute`, `cattr_accessor`, …), concern scopes, `has_rich_text`, model class methods on relations, `Current`'s class methods, mailer actions, `helper_method`s, view helpers, and instance-context overloads for macro lambdas. Methods copied elsewhere keep their inline types. Don't edit.
- `sig/shims/` — hand-written: gems without signatures (`sig/shims/gems/`), gaps in the Rails signatures, framework extensions from `lib/rails_ext`, concern contracts and domain interfaces (`models.rbs`), and the few classes inline RBS can't declare. Prefer fixing the generator over adding a shim for something the code declares.
- `.gem_rbs_collection/` — gem signatures from [gem_rbs_collection](https://github.com/ruby/gem_rbs_collection), installed by `bin/rbs collection install` (`rbs_collection.yaml`, locked in `rbs_collection.lock.yaml`). Not checked in.

## Writing annotations

```ruby
class Card::Mover
  attr_reader :card #: Card

  # @rbs @board: Board?

  #: (Card, ?board: Board?) -> void
  def initialize(card, board: nil)
    @card, @board = card, board
  end

  # @rbs users: Array[User] -- doc-style annotations work too
  # @rbs return: bool
  def move_to(users)
    # ...
  end
end
```


- Annotate public methods with real types; avoid `untyped` where the type is knowable.
- Unannotated methods are typed `(?) -> untyped`, except overrides: they inherit the superclass signature. So always annotate `initialize` (otherwise it's `Object#initialize`, `() -> void`) and overridden framework methods like a job's `perform`.
- Use `# @type var name: Type` for local variables Steep can't infer, such as empty collections, and `expr #: Type` to assert a type Steep can't prove (it only works at the end of a line).

## Rails patterns

Inline RBS can't express some Rails idioms, so the code follows these conventions:

- **Concerns** declare the type of the including class, so methods resolve against the model:

  ```ruby
  module Card::Closeable
    # @type instance: Card
    extend ActiveSupport::Concern

    included do
      # @type self: singleton(Card)
      has_one :closure
    end

    module ClassMethods
      # @type instance: singleton(Card)
      def closed_recently = closed.where(...)
    end
  end
  ```

  Concerns shared by several classes use their common superclass (`ApplicationRecord`, `ApplicationController`). Helpers use `ActionView::Base`. Don't use `# @rbs module-self: Card` for a concern that `Card` includes: RBS reports it as a circular mix-in.
- **Class methods**: use `def self.foo` (and `private_class_method def self.foo`), not `class << self`, whose methods inline RBS declares as instance methods. In concerns, use `module ClassMethods`, not `class_methods do`, for the same reason.
- **Mixins** of several modules (`include A, B`) or of non-constants (`extend self`, `include Rails.application.routes.url_helpers`) aren't supported inline. Mark them with `# @rbs skip -- declared in sig/generated/inline.rbs` and run `bin/rails rbs:inline`.
- **Macros that define methods** take their type from a trailing `#:`, like `attr_reader`. Without one, the methods are `untyped`:

  ```ruby
  store_accessor :fields, :card_ids, :column_ids #: Array[String]?
  class_attribute :push_targets, default: [] #: Array[singleton(Notification::PushTarget)]
  attribute :user #: User?
  ```

  Run `bin/rails rbs:inline` after adding or changing one.
- **Lambdas Rails runs with `instance_exec`** (`belongs_to ..., default: -> { ... }`, `rate_limit ..., with: -> { ... }`) are typed as instance code through generated overloads; blocks through the Rails signatures. To support another such macro, add it to `INSTANCE_LAMBDA_MACROS` in the generator.
- **Classes inline RBS can't declare** (a `Struct.new`/`Data.define` or computed superclass) are skipped with `# @rbs skip` and declared in `sig/shims/`.
- **`Current.user`, `Current.account`, `Current.identity` and `Current.session` are nilable**, as at runtime. Where the code requires one (controller actions behind authentication, tenanted jobs), use the bang reader — `Current.user!`, `Current.account!` — which raises if it's unset and is typed as present. Where it may be absent, handle `nil`.
- **Narrow nils with locals**, which Steep follows and STYLE.md prefers: `if account = Current.account` rather than `if Current.account` followed by `Current.account.slug`. Steep doesn't narrow repeated method calls.

## Limitations to know

- Put method annotations above the `def`. A trailing `#:` on an endless method (`def foo = 1 #: Integer`) isn't picked up.
- Declare instance variables (`# @rbs @name: Type`) before the first statement of the class body; anywhere else they're reported as unused.
- Inside a compact `class A::B`, constants resolve against `A::B` only, as in Ruby, so spell out ambiguous names: `::Storage::Entry`, `::Data`.
- If an RBS definition can't be built (say, a method declared twice), Steep logs an `ERROR` and treats the type as `untyped`, which hides errors. A passing check with `ERROR` lines in its output isn't clean.

## Ignoring diagnostics

`# steep:ignore NoMethod` silences one diagnostic on its line. It's a last resort, for what Steep genuinely can't express, such as `**options` forwarded to a method with required keywords, or a constant only the SaaS engine defines.

- Fix the type instead when you can: correct a signature, narrow with a local, use a bang reader, or add a type assertion on its own line with the reason.
- Name the diagnostic, and explain why on the line above (`# steep:ignore X -- reason` isn't supported).
- Delete it once it's not needed: Steep reports redundant ignores.
- Don't use it to hide a bug. Let the check fail until the bug is fixed.
