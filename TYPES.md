# Types

Ruby code in `app/` and `lib/` is typed with [RBS](https://github.com/ruby/rbs) comments and checked with [Sorbet](https://sorbet.org), which reads them as [RBS signatures](https://sorbet.org/docs/rbs-support). `bin/srb tc` must pass.

Use the types: read a method's signature to learn what it takes and returns, and annotate the code you write. The goal is type checking that catches mistakes, so prefer code that type-checks over silencing Sorbet.

Write types only as comments. Don't use Sorbet's Ruby syntax (`sig { }`, `T.let`, `T.must`, `extend T::Sig`) in app code: every construct has an RBS comment form (below).

## Commands

- `bin/srb tc` — type check everything (about half a second). Configured in `sorbet/config`.
- `bin/tapioca dsl` — regenerate the RBIs for Rails' generated methods (`sorbet/rbi/dsl/`). Run it after changing the schema, associations, scopes, concerns, routes, mailers, or macros with `#:` types (`attribute`, `store_accessor`, `class_attribute`, …). It loads the app, so it takes several seconds.
- `bin/tapioca gems` — regenerate gem RBIs after changing the bundle. `bin/tapioca annotations` updates community annotations.
- Editor support: run `bin/srb tc --lsp` as a language server (the Sorbet VS Code extension and Ruby LSP do this). It gives diagnostics, hover, go to definition, references, completion, and renames.

## Where types live

- Inline RBS comments in the Ruby source — the default.
- `sorbet/rbi/dsl/` — generated by `bin/tapioca dsl`: columns, associations, enums, scopes, relations, URL helpers, mailers, controller helpers, current attributes, and more. Don't edit.
- `sorbet/tapioca/compilers/` — our Tapioca compilers, for Rails patterns the built-in ones miss:
  - `RequiredAssociations`: a required `belongs_to` is present, not nilable.
  - `IncludedBlockMixins`: mixins inside a concern's `included do ... end` block.
  - `RelationClassMethods`: model class methods on relations.
  - `Annotated*` (`annotated_macros.rb`): types for macros from a trailing `#:` comment.
- `sorbet/rbi/gems/` and `sorbet/rbi/annotations/` — generated by `bin/tapioca gems` and `bin/tapioca annotations`. Don't edit.
- `sorbet/rbi/shims/` — hand-written RBIs: gaps in gem and Rails RBIs, framework extensions from `lib/rails_ext`, concern contracts, and the few classes Sorbet can't read. Prefer a compiler over a shim for something the code declares.

Tapioca translates RBS comments into runtime signatures while it loads the app, so generated RBIs keep the types you write inline. For example, `Current.user!` and the mailer actions are typed.

## Writing types

Every Ruby file starts with a sigil. Sorbet reads RBS comments only in files that have one:

```ruby
# typed: true
class Card::Mover
  #: Card
  attr_reader :card

  #: (Card, ?board: Board?) -> void
  def initialize(card, board: nil)
    @card, @board = card, board
  end

  #: (Array[User]) -> bool
  def move_to(users)
    # ...
  end
end
```

- Put a method's signature in a `#:` comment directly above the `def`. Continue a long one on `#|` lines. Doc-style `# @rbs x: Type` annotations aren't supported: Sorbet ignores them silently.
- Put an attribute's type in a `#:` comment above `attr_reader`/`attr_accessor`. A trailing `#:` there is an assertion on the call, not the attribute's type.
- Parameter kinds, names and order in the signature must match the `def`.
- Annotate public methods with real types; avoid `untyped` where the type is knowable.

### Assertions

| Comment | Means | Use when |
|---|---|---|
| `x = expr #: Type` | `T.let` | Declaring a variable's type. The value must be a `Type`. |
| `expr #: as Type` | `T.cast` | You know more than Sorbet, e.g. after a check it can't follow |
| `expr #: as !nil` | `T.must` | A value is present by an invariant (say why) |
| `#: self as Type` (own line) | `T.bind` | A block or lambda runs with a different `self` |
| `expr #: as untyped` | `T.unsafe` | Last resort (see below) |

## Rails patterns

- **Concerns** declare what they're mixed into with `# @requires_ancestor:` above the module. Blocks that Rails runs in the class bind `self`:

  ```ruby
  # @requires_ancestor: Card
  module Card::Closeable
    extend ActiveSupport::Concern

    included do
      #: self as singleton(Card)
      has_one :closure
    end

    # @requires_ancestor: singleton(Card)
    module ClassMethods
      #: () -> Card::PrivateRelation
      def closed_recently = closed.where(...)
    end
  end
  ```

  Every class that includes the concern must have the required ancestor, so require what's actually common: `ApplicationRecord` for concerns several models share, a narrow helper module for helpers that models include too. Declare what a shared concern needs from its records in `sorbet/rbi/shims/models.rbi`.
- **Class methods**: use `def self.foo` (and `private_class_method def self.foo`), and `module ClassMethods` in concerns.
- **Macros that define methods** take their type from a trailing `#:` comment, read by our Tapioca compilers. Run `bin/tapioca dsl` after adding or changing one:

  ```ruby
  attribute :user #: User?
  store_accessor :fields, :card_ids, :column_ids #: Array[String]?
  class_attribute :push_targets, default: [] #: Array[singleton(Notification::PushTarget)]
  ```

- **Lambdas Rails runs with `instance_exec`** (`belongs_to ..., default: -> { ... }`, `rate_limit ..., with: -> { ... }`) are typed in the class's context. Bind `self` on the lambda's first line:

  ```ruby
  belongs_to :account, default: -> {
    #: self as Card
    board.account
  }
  ```

- **Relations** are `Card::PrivateRelation`, `Card::PrivateCollectionProxy`, and `Card::PrivateAssociationRelation`.
- **`Current.user`, `Current.account`, `Current.identity` and `Current.session` are nilable**, as at runtime. Where the code requires one (controller actions behind authentication, tenanted jobs), use the bang reader — `Current.user!`, `Current.account!` — which raises if it's unset and is typed as present. Where it may be absent, handle `nil`.
- **Narrow nils with locals**, which Sorbet follows and STYLE.md prefers: `if account = Current.account` rather than `if Current.account` followed by `Current.account.slug`. Sorbet doesn't narrow repeated method calls.

## Limitations to know

- **No structural interfaces.** RBS interfaces (`_Foo`) aren't supported, and Sorbet types are nominal: a value matches a module type only if its class includes the module. Use classes, modules the code includes, or unions.
- **Sigils are required** in every file with RBS comments; `--typed` doesn't count.
- **Methods with `(...)` parameters** can't have an RBS signature: Sorbet fails to parse the file.
- **Dynamic superclasses and mixins** (`class X < Data.define(...)`, `include const_get(...)`) are errors in any file. Use a constant, or declare the class in a shim.
- **Constants and mixins inside blocks** (`included do`) are invisible to Sorbet. The `IncludedBlockMixins` compiler covers `include`/`extend`; define constants in the module body.

## Silencing errors

Sorbet has no ignore comments. `#: as untyped` turns a value into `T.untyped`, which silences every check on it. It's a last resort, for what Sorbet genuinely can't express.

- Fix the type instead when you can: correct a signature, narrow with a local, use a bang reader, bind `self`, or cast with a reason.
- Explain why on the line above.
- Don't use it to hide a bug. Let the check fail until the bug is fixed.
